# Spike S5: поиск по-русски

Дата: 2026-10-28. Бюджет по спецификации — до 3 ч. Решение — `docs/adr/0008-search.md`. Код — этот крейт (вне workspace): `cargo run --release -- pairs | prefix | tokenizer | bench [N] | cold`, база для замеров лежит в каталоге из `S5_DIR`.

Машина: Apple M3 Pro, 18 ГБ, macOS 26.5.2, SQLite 3.53.2 (бандл `rusqlite 0.40`), Rust 1.94, режим `--release`. WAL, `synchronous=NORMAL`.

## Корпус
Настоящих данных в репозитории нет, поэтому корпус сгенерирован (`src/corpus.rs`, детерминированный): 100 000 записей за 5 лет (1826 дней), 40 чатов, 48,9 МБ текста (в среднем 490 байт; настоящее «Избранное» пользователя — около 650 байт на запись). Словарь — 574 вручную написанные словоформы плюс 40 000 псевдослов, частоты по Ципфу. В 30 % записей подмешано каждое из пяти «частых» слов, в 2 % — «купить молоко», редкие слова встречаются 2–5 раз. Результат по скорости зависит от распределения слов; оно искусственное, но худший случай (слово в 30 % записей) взят намеренно.

## Стеммер
`rust-stemmers 1.2.0` (Snowball, русский и английский): лицензия MIT/BSD-3-Clause, последний релиз 17.11.2019 (поддержки нет, алгоритм Snowball не меняется), 39,8 млн загрузок на crates.io, зависимости `serde` и `serde_derive`. `cargo build --release --target wasm32-unknown-unknown` крейта с ним проходит. Критерий отказа не сработал. Сборка самого `kinige-domain` с ним — в задаче 4.4.

## Словоформы (50 пар, `pairs`)
Совпало с ожиданием 50 из 50, где ожидание («связаны» или «не связаны») записано до запуска. Все «да»-пары (книга/книги/книгу/книгой/книгам, ёлка/елка, длинный/длиннее, молоко/молока/молоком, работать/работал, красивый/красиво, run/running/runs, city/cities…) связаны. Известные промахи, которые стеммер не связывает (ожидаемо, это не ошибки реализации):

| пара | причина |
|---|---|
| бежал / бегу | чередование согласных в корне |
| человек / люди, ребёнок / дети | разные основы |
| идти / шёл | супплетивизм |
| хороший / лучше | сравнительная степень от другой основы |
| день / дня | беглая гласная (`ден` / `дня`) |
| happy / happier, write / written, go / went | английские нерегулярные |

«йод» и «иод» не сливаются: стеммы `йод` и `иод`, а `unicode61` не склеивает «й» с «и» ни при каком `remove_diacritics` (`tokenizer`). Но он не склеивает и «ё» с «е» (`елка` не находит `ёлка`), поэтому «ё» → «е» делает Rust до индекса и до запроса.

## Префикс незаконченного слова (`prefix`)
Для каждой из 574 словоформ проверен каждый префикс длиной от 2 знаков: находит ли запрос документ с этой формой.

| индекс | запрос для последнего слова | найдено |
|---|---|---|
| только стеммы | `stem(p)*` | **99,0 %** (2834 из 2863) |
| только стеммы | `p*` | 72,8 % |
| только стеммы | `stem(p)* OR p*` | 99,0 % |
| стеммы и исходные слова | `p*` | 100 % |

«моло» → стемм `мол`, и `мол*` находит `молок`; «длинн» → `длин`, и `длин*` находит стемм слова «длинный» (`длин`). Прямой префикс `p*` без исходных слов не работает (в стемме `длин` нет «нн»), `OR p*` ничего не добавляет. Промахи `stem(p)*` — префиксы, обрывающиеся посреди неузнанного окончания: «длинног» (до «длинного»), «большог», «бежат»; после следующей буквы запрос снова находит запись. Оставшийся 1 % против роста индекса: со словами 34,3 МБ против 25,7 МБ.

Минимальная длина префикса — 2 знака: один знак превратил бы запрос в `м*` по четверти индекса, слово из одного знака ищется как обычный терм.

## Раскладка FTS5 (100 000 записей, `bench`)
Объём текста 48,9 МБ; база без индекса 75,0 МБ. «К тексту» — размер индекса, делённый на объём текста (успех: ≤ 1,5).

| вариант | индекс, МБ | к тексту | вставка пачкой, мкс/зап | вставка по одной, мкс | удаление по одной, мкс |
|---|---|---|---|---|---|
| **v1** contentless (`contentless_delete=1`) + таблица `rowid → message_id`, стеммы | **25,7** | **0,53** | 13 | 244 | 87 |
| v1s то же, стеммы и исходные слова | 34,3 | 0,70 | 26 | 211 | 230 |
| v2 external content (таблица стеммов + `content=`) | 74,2 | 1,52 | 15 | 249 | 198 |
| v3 обычная таблица, `message_id UNINDEXED` | 69,3 | 1,42 | 14 | 386 | **21 988** (полный просмотр) |
| t3 триграммы, contentless, нижний регистр | 96,7 | 1,98 | 38 | 357 | 285 |

v1 по `dbstat`: `fts_data` 11,4 МБ, таблица соответствия 4,6 МБ и её уникальный индекс 5,0 МБ, `fts_docsize` 1,2 МБ. У `rowid` таблицы `message` после `VACUUM` номер может смениться (первичный ключ — текст), поэтому соответствие хранится отдельной таблицей.

`index_text` на 100 000 записей: 1,29 с (12,9 мкс на запись) — это нормализация и стемминг при импорте 100 000 записей.

## Скорость запроса (мс, p50 / p95 / max; `LIMIT 50`, порядок `(journal_date, created_at, id)` по убыванию, `deleted_at IS NULL`)
Форма A: соединение от FTS к `message`, сортировка найденных (план: `SCAN fts`, поиск по `rowid` соответствия и по `id`, временное дерево для `ORDER BY`; индекс по датам не нужен). Форма B: обход индекса `message(journal_date, created_at, id)` с проверкой `id IN (…FTS…)`.

| вариант и форма | редкое | частое (30 %) | два слова | префикс | частое, страница в глубине (keyset) |
|---|---|---|---|---|---|
| **v1 A** | 0,0 / 0,9 / 1,6 | 48,1 / 69,1 / 363¹ | 24,6 / 33,7 / 36,2 | 24,6 / 57,6 / 66,1 | 47,7 / 60,9 / 108,7 |
| v1 B | 0,0 / 0,3 / 0,4 | 65,4 / 95,2 / 114,8 | 26,3 / 31,5 / 41,3 | 27,9 / 79,9 / 84,9 | 70,3 / 101,8 / 129,2 |
| v2 A | 0,0 / 1,0 / 2,3 | 47,9 / 64,1 / 523¹ | 21,6 / 44,9 / 74,3 | 27,6 / 57,5 / 94,5 | 47,9 / 54,3 / 98,4 |
| v3 A | 0,0 / 1,0 / 2,8 | 55,8 / 71,4 / 544¹ | 24,0 / 33,6 / 49,6 | 33,1 / 83,1 / 128,8 | 56,2 / 81,4 / 111,6 |

¹ Первый прогон на только что записанном файле (страницы не в кэше ОС). В отдельной серии (`cold`: 5 новых соединений подряд, файл в кэше ОС) первый запрос частого слова — 45 мс (максимум 357 мс на самом первом из пяти), второй — 44 мс; `mmap_size` 256 МБ снижает оба до 29 и 26 мс, но не нужен. **p95 всех классов запросов в форме A — не больше 70 мс при цели 300 мс.**

Триграммы: запросы из 1–2 знаков возвращают 0 строк, «мол» находит 24 699 записей (по подстроке, а не по основе); индекс 1,98 × текста. Для словоформ не годятся, для короткого префикса всё равно нужен стемм, поэтому в слайс не входят.

## Критерии успеха
| критерий | результат |
|---|---|
| словоформы находятся | да, 50 из 50 ожиданий; промахи перечислены |
| p95 на 100 000 < 300 мс | да: ≤ 70 мс (форма A, v1) |
| индекс ≤ 1,5 × текста | да: 0,53 (v1); v2 (1,52) не проходит |
| вставка < 1 мс | да: 13 мкс пачкой, 244 мкс по одной в своей транзакции |
| `wasm32` | да |

## Не проверено
- Скорость на настоящих текстах пользователя (распределение слов иное).
- Поведение при 1 млн записей: форма A сортирует все найденные, время растёт линейно от числа совпадений.
- Фильтр по чату вместе с поиском: план запроса не снимался.
