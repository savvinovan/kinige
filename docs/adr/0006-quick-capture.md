# ADR-0006: Быстрый захват — окно, хоткеи, трей, дописывание, черновики

Дата: 2026-10-22. Статус: **принято** (слайс 2). ТЗ §1.1, §2.1, §3.2, §5, §5.1, §9.3, §12.3, §15; ADR-0001 §3.3, §3.4, §4, приложение §A.0.

## Контекст
Слайс 2 добавляет второе окно (быстрый захват), два глобальных сочетания, значок в menu bar, жизненный цикл «окно закрыто, приложение живёт», черновики и первую перезапись одной группы (`body`) — дописывание к последней записи.

## Решение

**Окно.** Второе окно Tauri `capture`, объявлено в `tauri.conf.json` и создаётся скрытым при старте: без заголовка, поверх всех окон, на всех рабочих столах, 560 × 360 (токены `layout.capture.*`). Страница та же (`index.html#capture`), приложение выбирает компонент по хэшу. У окна своя capability `capture-window`: пять команд `capture_state`, `capture_send`, `capture_append`, `capture_save_draft`, `capture_hide` — без `chat_id` (только Inbox), без чтения ленты, без `core:*`, без событий и плагинов. Главному окну добавлены `get_draft`, `save_draft`, `set_shortcut`, `reset_shortcut`, `shortcut_recording` и `core:event:allow-listen` / `allow-unlisten` (событие «записи изменились»). Отрицательные тесты — `src-tauri/tests/ipc.rs`, `tests/config.rs`.
- Rust сообщает окну захвата о показе и просьбе спрятаться через `WebviewWindow::eval` (событие DOM), а не событием Tauri: права слушать события у окна нет. Главному окну событие «записи изменились» идёт через `emit_to("main")`.
- Показ: окно ставится на экран с курсором (`cursor_position` + `monitor_from_point`). Скрытие: хоткей при открытом окне, Esc, потеря ключевого статуса (не раньше 900 мс после показа) и закрытие окна просят страницу сохранить черновик и вызвать `capture_hide`; если страница не ответила за 600 мс, окно прячется принудительно.
- **macOS: окно захвата — неактивирующая панель NSPanel (`tauri-nspanel` 2.1.1). Статус: принято** (решение владельца продукта 22.10.2026: Mac App Store не планируется, поведение как у Spotlight и Raycast).
  - **Зачем.** Панель с флагом `NonactivatingPanel` становится ключевой, не активируя приложение: прежняя программа остаётся активной и после скрытия панели сама сохраняет фокус, главное окно не всплывает, `AppHandle::hide` и его побочное действие (прячутся все окна приложения) не нужны. Это свойство продукта, а не обход сбоя.
  - **Чего исходное обоснование не доказывало.** Первая реализация (обычное окно, `show` + `set_focus`) на macOS 26.5 в живой проверке то получала ввод, то нет: окно получало ключевой статус и через 1–10 мс теряло его (`windowDidBecomeKey` → `windowDidResignKey`, события `NSEventTypeProcessNotification`), клавиши уходили не в страницу. Тогда это объяснили «кооперативной активацией» macOS 14+ и особенностями Finder и стороннего ассистента. **Это объяснение не подтверждено.** Позже выяснилось, что на машине проверки ⌥Space занят ChatGPT (`KeyboardShortcuts_toggleLauncher`): каждое нажатие ⌥Space при проверке открывало ещё и окно ChatGPT, оно активировалось и перехватывало фокус, а значит, смена активной программы (`ProcessNotification`, «оверлей ассистента», «front=Gemini/ChatGPT») была следствием конфликта сочетаний, а не свойством обычного окна Tauri. Обычное окно со свободным сочетанием после этого не перепроверялось, поэтому утверждать, что оно «ненадёжно», нельзя; NSPanel выбран по причинам из пункта «Зачем».
  - **Цена.** Флаг `macOSPrivateApi` в `tauri.conf.json` (приватный API; закрывает Mac App Store, который не планируется) и сторонний крейт (2.1.1, проверен по исходникам: класс окна подменяется на подкласс `NSPanel`; сбой преобразования — ошибка старта, а не тихая деградация). Откат — один коммит (`665302e`).
  - **Все вызовы AppKit — на главном потоке** (`run_on_main_thread`): показ, скрытие и возврат ключевого статуса панели. Вызов `show_and_make_key` / `hide` из потока обработки хоткея буфера и из запасного таймера скрытия ронял приложение (SIGTRAP, найдено ревью).
  - **Возврат ключевого статуса (`rekey`, `MAX_REKEYS = 20`) — пока оставлен, перепроверка не выполнена.** Статус возвращается панели, если система сняла его раньше чем через 300 мс после получения; иначе потеря статуса — уход пользователя, окно прячется с сохранением черновика. Цикл появился из-за снятий статуса, которые, вероятнее всего, вызывал ChatGPT (см. выше), поэтому с свободным сочетанием он, возможно, не нужен. Проверка «со свободным сочетанием ⌃⌥⇧K над Finder и над другой программой, считать снятия» подготовлена, но в раунде исправлений **не выполнена: экран был заблокирован** (`CGSSessionScreenIsLocked`), нажатия не посылались. Пока нет прогона без снятий, цикл остаётся (безвреден: ограничен 20 возвратами и только в первые 300 мс после показа).
- На Windows и Linux (слайс 10) остаётся обычное окно `show` + `set_focus`.

**Дописывание — первая перезапись группы** (`kinige_domain::append`, ADR-0001 §3.3, §3.4, §4).
- Цель: последняя неудалённая запись Inbox, `origin = 'user'`, `created_at` не старше 10 минут (граница включительно), `journal_date` = сегодня, все группы в поддерживаемой `sv` (иначе запись только для чтения, ADR §4 п. 4). Повреждённый `hlc_json` — ошибка, а не «нельзя». Правило решает Rust в той же транзакции, что и запись.
- Текст: `старый + "\n\n" + новый` (новый абзац; `breaks: true` склеил бы строки); лимит 512 КиБ — по каноничным байтам группы после склейки (`message_too_large`, ничего не записано, новая запись вместо отказа не создаётся).
- Группа `body` переписывается каноничными байтами с новым HLC строго больше прежнего: `edited_at = now`; `base`/`supersedes` по §3.4 — версию подтвердил сервер (`server_known = 1`): `base = hlc(V)`, `supersedes = []`; собственная неподтверждённая: `base = V.base`, `supersedes = V.supersedes ∪ {hlc(V)}`, не больше 64 (старейшие отбрасываются). Остальные группы, неизвестные группы, неизвестные поля `body` и лишние поля записей `hlc_json` сохраняются дословно; `schema_version` — максимум `sv` по группам. HLC `body` — одна запись в `sync_state` той же транзакцией.
- **Ревизии `edit` нет:** старый текст — префикс нового, ничего не теряется. Таблица ревизий — слайс 3.
- `created_at` и `journal_date` не меняются; запись остаётся на месте в ленте; `mirror_dirty` дня записи.

**Черновики.** Миграция 2: локальная несинхронизируемая таблица `draft(key, body, updated_at)`; ключи `capture` и `chat:<id>`. Фронтенд сохраняет с задержкой 300 мс и при скрытии; Rust очищает черновик в транзакции отправки (свой ключ у каждого пути: хоткей буфера черновиков не трогает). Предел — 1 МиБ. В Markdown-копию и в таблицы записей черновики не попадают.

**Сочетания.** Каноничная запись `Ctrl+Alt+Shift+Cmd+<KeyboardEvent.code>` (`kinige_domain::shortcuts`): те же имена понимает `global-hotkey`, раскладка не влияет. Нужен Ctrl, Alt или Cmd; ⌘Q/W/H/M/Space зарезервированы. По умолчанию ⌥Space (захват) и ⌥⇧V (буфер) — решение пользователя 22.10.2026; хранятся в `app_setting`, не синхронизируются. Смена: проверка записи и совпадения с другим действием (ничего не меняется) → регистрация нового в системе (отказ — `shortcut_taken`, прежнее продолжает работать) → сохранение (сбой — новое снимается) → снятие прежнего. Сочетание, которое система не приняла при старте, показывается в «Настройках» как «не назначено», остальное работает. На время записи нового сочетания хоткеи не срабатывают (иначе нельзя нажать уже назначенное).

**Хоткей буфера.** Текст из буфера читает `arboard` 3.7 (`get_text`) только из Rust, на отдельном потоке; не текст или пусто — ничего; успех — запись в Inbox, событие главному окну и двойное мигание значка в menu bar (160 / 110 мс, без звука и окна); сбой записи — окно захвата с текстом буфера в поле и ошибкой (текст — в черновик и в память).

**Трей и жизненный цикл.** Ядро Tauri, фича `tray-icon`: template-иконка (`web/src/ui/icons/tray/*.svg` → PNG), меню «Новая заметка» / «Inbox» / «Выйти»; строки — из `web/src/locales/{en,ru}.json` (`include_str!`). Закрытие главного окна прячет его; Dock (`RunEvent::Reopen`), меню трея и второй запуск (`tauri-plugin-single-instance`, подключён первым) показывают его; ⌘Q и «Выйти» завершают.

## Зависимости
`tauri` 2.12.4 + фичи `tray-icon`, `image-png`; `tauri-plugin-global-shortcut` 2.4.1 (тянет `global-hotkey` 0.8.0, на macOS — Carbon `RegisterEventHotKey`); `tauri-plugin-single-instance` 2.5.4; `tauri-nspanel` 2.1.1 (только macOS; требует фичу `macos-private-api` у `tauri` и `macOSPrivateApi: true` в конфиге); `arboard` 3.7.0 без фичи `image-data`. Последние на crates.io — `3.0.0-alpha.3` у обоих плагинов (для Tauri 3), поэтому взята последняя стабильная ветка 2.x.

## Отклонено
- Обычное окно Tauri для захвата на macOS: активирует приложение (поднимает главное окно, требует `AppHandle::hide` для возврата фокуса). Не отвергнуто как «ненадёжное» — это не доказано (см. выше); отвергнуто как не Spotlight-подобное. Остаётся запасным путём на Windows и Linux.
- Обнаружение «сочетание занято другой программой» на macOS (`CopySymbolicHotKeys` для системных сочетаний; чужие программы через `RegisterEventHotKey` не видны): **отложено**, в этом слайсе его нет; состояние «не назначено» работает в данных, интерфейсе и тестах.
- Выбор чата в окне захвата, ⌘Enter в главном окне, последние чаты кроме Inbox — слайс 3.
- Ревизия `edit` при дописывании — лишняя запись, когда текст только растёт (слайс 3 вводит ревизии для правок).
- JS-плагин буфера обмена и JS-плагин сочетаний: окна не получают прав на плагины, всё идёт через наши команды (§12.3).

## Последствия
Для `sync-crypto-guardian`: миграция 2 (`draft`), перезапись `body` с `base`/`supersedes`, сохранение неизвестных групп и полей. Тесты, отложенные из слайса 1 (неизвестная группа, лишние поля `hlc_json`, строго растущий HLC, повреждённый JSON, отказ записи), возвращены: `crates/kinige-domain/src/append.rs`, `crates/kinige-store/tests/capture.rs`; тестовые хелперы удаления (`mark_deleted`) ставят `deleted_at` вместе с согласованными группой `deleted` и её HLC, а не прямым `UPDATE` колонки.
