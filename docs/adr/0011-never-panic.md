# ADR-0011: «Никогда не падать» — линты вместо дисциплины, паника не теряет данные

Дата: 2026-11-01. Статус: **принято** (задача техдолга KINIG-28, не слайс). ТЗ §12 (качество), ADR-0009 (панику в задаче писателя и вызове MCP ловит `catch_unwind`).

## Контекст
Приложение — личный журнал: падение посреди записи или при запуске хуже, чем любая ошибка в окне. До задачи правило держалось на дисциплине (`unwrap` в коде приложения почти не было), но ничто его не проверяло, а в журнал паники не попадали.

## Решение

**Линты (`Cargo.toml`, `[workspace.lints]`, `deny`).** `clippy::unwrap_used`, `expect_used`, `panic`, `unreachable`, `todo`, `unimplemented`, `indexing_slicing`, `string_slice`; `unsafe_code`. Поведение в тестах задаёт `clippy.toml` (`allow-unwrap-in-tests`, `allow-expect-in-tests`, `allow-panic-in-tests`, `allow-indexing-slicing-in-tests`, `allow-print-in-tests`; для `unreachable`, `todo`, `unimplemented` и `string_slice` настройки у clippy 1.94 нет).
- Корень каждого интеграционного теста (`tests/*.rs`) начинается с `#![cfg(test)]`: иначе clippy не считает хелперы вне `#[test]` тестовым кодом. Примеры (`examples/`) и `build.rs` разрешают нужное строкой `#![allow]` с причиной.
- `unsafe_code = "deny"`, а не `forbid`: единственный `unsafe` — `geteuid` в `effective_uid` (`kinige-store/src/settings_file/io.rs`), в `std` нет безопасного аналога, зависимость ради одного вызова хуже одной обоснованной строки. Тест `ipc_restore_e2e` (macOS) вызывает `set_var`, в 2024 это `unsafe`: `#[allow(unsafe_code)]` на тесте.
- Исключение для кода приложения — доказуемо безошибочный литерал: `#[allow(clippy::expect_used)]` и `.expect("почему не может упасть")`. Сейчас исключений нет.
- Крючки для тестов страховки (`panic_in_read_for_test`, `panic_in_agent_read_for_test`, флаги `panic_next` у копии, обслуживания и слушателя MCP) паникуют намеренно: первые два помечены `#[allow(clippy::panic)]`, флаги срабатывают только при `debug_assertions`, в релизе их нет.
- `arithmetic_side_effects` не включён: 199 срабатываний на счётчики и итераторы, не зависящие от ввода (проверено запуском). Длины и смещения из ввода просмотрены вручную, выделения всегда пропорциональны уже полученным данным (запись ≤ 512 КиБ, кадр MCP ≤ 4 МиБ, файл настроек ≤ 1 МиБ, импорт ≤ 1 ГиБ).

**Страховка.**
- `panic = "unwind"` во всех профилях; тест `config.rs` падает, если в манифесте появится `panic = "abort"`.
- Хук паники (`src-tauri/src/panic_hook.rs`) пишет в `kinige.log` только поток и место (файл:строка); текст паники не пишется (в нём бывают данные), путь внутри зависимостей обрезан до `<крейт-версия>/src/…`.
- Обработчик команд Tauri обёрнут в `catch_unwind` (`guarded`): паника в синхронной части (разбор аргументов, синхронная команда на главном потоке) не уносит процесс. Ограничение, проверенное по исходникам tauri 2.12: панику в асинхронной части команды ловит только задача tokio — процесс жив, но вызов без ответа (промис окна не завершается); чтение, запись и вызовы агента в `kinige-store` ловят панику сами и отвечают ошибкой.
- Ошибка запуска (`setup`, сборка приложения) — запись в журнал (только категория) и выход с кодом 1, не паника (tauri сам паникует на ошибке `setup`).
- Потоки запускаются через `thread::Builder::spawn`, отказ ОС — ошибка (`StoreError::Internal` / запись в журнал). Отравленные мьютексы восстанавливаются (`unwrap_or_else(PoisonError::into_inner)`): раньше часть мест молча пропускала работу, а поток ожидания копии при отравлении крутился без пауз.

**Охотники за паникой.** `src-tauri/tests/panic_hunter_ipc.rs` — каждая команда каждого окна (в том числе без открытого хранилища) получает пустые, не те по типу и враждебные по значению аргументы; `panic_hunter_mcp.rs` — то же для всех инструментов MCP по настоящему сокету; `kinige-domain/tests/hostile_input.rs` — многобайтовые знаки на каждой позиции образцов для всех разборщиков домена.

## Последствия
- Новый `unwrap` в коде приложения не пройдёт CI. Нужен — `Result`, `?`, `get()` или обоснованное исключение выше.
- Найденные при этом реальные проблемы (в журнале задачи KINIG-28): квадратичное время разбора тегов и фрагментов на строке вида `[a](`×N или `<a`×N (до 20 с на строке в 200 КБ) — введён предел вложенности скобок 64 и однократный поиск закрытия; `std::env::args()` паниковал на аргументе запуска не в UTF-8; `app.state::<Store>()` в хоткее буфера паниковал бы без открытого журнала.
