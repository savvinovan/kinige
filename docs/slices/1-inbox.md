# Slice 1: Inbox, the first real entry

Budget: 6 days, as one slice (user decision 21.10.2026; started 21.10.2026 19:47 MSK). **Actual:** implementation took 51 min (until 20:39), first ready for acceptance at 21:23 (1 h 36 min), merged 22.10.2026 02:30 (6 h 43 min, including fixes after looking at the live window, reviews and CI reruns due to network problems). Estimates for the following slices are in hours. Depends on: D1, ADR-0001, ADR-0004 (accepted). Sources: PRD §2.1, §3.2, §4, §5, §6, §12.3, §15; ADR-0001 §1–§4, appendix §A.0, §C; `docs/screens/D1/README.md` («Открытые вопросы к слайсу 1», “Open questions for slice 1”).

## Scenario
1. I launch a built Kinige on a clean machine: the sidebar has one chat, Inbox, the feed is empty, the cursor is in the input field. If the system is in Russian, the UI is Russian; in any other language, it is English.
2. I type «Купить **молоко**» (“Buy **milk**”), Shift+Enter, «- [ ] позвонить маме» (“- [ ] call mom”), Enter. In under 100 ms the entry is at the bottom of the feed under the “Today” label: the Markdown is rendered, the entry shows its time, the Inbox counter is 1. No toast and no confirmation: the entry simply appears (changed by the user on 21.10.2026 after looking at the window; there used to be an “Undo” toast here).
3. I send a second entry: it likewise simply appears below the first, the counter is 2. There is no undo for sending: an entry is removed by deleting it and changed by editing it, from the hover actions (slice 3). (The former step 3, “Undo” puts the text back in the field, was dropped.)
4. I click the link `https://example.com` in an entry: it opens in the system browser, and the Kinige window stays where it is. Right click → “Open Link” does not navigate the window away either.
5. `kill -9`, launch again: the entries are in place, same order and same time.
6. The copy is on from the first entry, in `~/Documents/Kinige`. Profile → “Settings”: I see the copy folder and the warning “the copy is plain text”, and I can choose another folder. In Finder there is `Kinige/Inbox/2026/2026-10-21.md` with the entries and their times; a new send updates the file within seconds, and if the process is killed right after sending, at the next launch. “Text size” → “Large”: larger immediately and after a restart.
7. I go through the real window with the Tab key: focus reaches every button, link and menu item.

## Included
- **Storage** `crates/kinige-store` (rusqlite, a single writer thread, WAL, §3.2). Migration 1: `chat`, `message` with all columns of §4.2 and ADR §C (`hlc_json` with `sv` per group, `server_known`, `groups_raw`, `origin`, `ext_json`; `base`/`supersedes` inside the groups); `sync_state` (`device_id`, `hlc_l`, `hlc_c`); local unsynced `app_setting` and `mirror_dirty(chat_id, journal_date)`. Inbox has a constant id and a constant `core` (ADR §3.6) and is created idempotently at first start; the value of the constant is added to the ADR-0001 appendix; the stored name is empty, and the UI shows the translated one.
- **`kinige-domain`** (no IO, wasm32): HLC (ADR §2, with the counter continuing after a restart), canonical JCS bytes of groups (ADR §3.3), a new entry created right away with all five groups (§A.0) and `sv = 1`, `journal_date` with the day boundary at 04:00 (§4.1), a check of the link scheme (only `http`, `https`, `mailto`).
- **Sending (§5):** command → one transaction (message + HLC in `sync_state` + `mirror_dirty`) → response → entry in the feed. No optimistic display: if the write fails, the text stays in the field with an error above it (D1 state). Success comes without a toast and without any other feedback. There is no undo for sending (the “Undo” decision was reversed by the user on 21.10.2026, see below); the `deleted` group and the trash are slice 3.
- **The main window on `TauriApi`** instead of the temporary D1 screen: Inbox with a real counter; the feed ordered by `(journal_date, created_at, id)`, the last page by a keyset cursor from Rust, day labels by `journal_date`; the input field (Enter, Shift+Enter, Enter inside a code block); no toast after sending. The “file”, “emoji” and “microphone” buttons are not in the app, so there are no dead buttons (§5); they stay in Storybook. The row of hover actions is as in D1. `MockApi` implements the same `KinigeApi` in memory; the `Demo*` types are replaced with generated ones (ADR-0002).
- **Markdown copy (§2.1):** after commit, a background task rewrites the whole day file `Kinige/<chat>/YYYY/YYYY-MM-DD.md` (temporary file + rename); without the trash (§16); a day with no entries means the file is deleted; leftover marks are processed at start. The Inbox folder is `Inbox` in any language (the path does not depend on the language). The format does not depend on the language (ISO date, 24-hour time); headings inside entries do not break the structure. An unavailable folder shows an error in Settings, the marks are not lost, and the write is retried.
- **Settings** is a modal inside the main window (no second window and no capability of its own), opened from the profile menu: the copy folder (the system dialog is called from Rust; path, status, the “plain text” warning, §12.3) and “Text size”: “Normal” / “Large” ×1.25 (ADR-0004). Stored in `app_setting`, not synced. “Export” and “About” stay “Coming soon”.
- **Links (§6, §12.3):** the command `open_external_url`; the scheme is checked in `kinige-domain`, opening goes through `tauri-plugin-opener` from Rust only (the window has no JS permissions for the plugin). `on_navigation` (`plugin::Builder::on_navigation`, present in tauri 2.12.4) lets through only the app's address, which closes off “Open Link”. The main window's capability lists only this slice's commands (§12.3).
- **i18n:** all UI strings, including the D1 strings (input field, profile menu, “Coming soon”, “Today”/“Yesterday”, errors, screen reader labels), go into `web/src/locales/en.json` and `ru.json`. The library is **i18next + react-i18next**: plurals through the built-in `Intl.PluralRules` (CLDR; for ru: one/few/many/other); no macros and no compile step (Vite 8, Storybook 10, Vitest 5 stay untouched); keys are typed from `en.json` (a missing key is a `tsc` error); translations are in the bundle, initialization is synchronous. Rejected: Lingui (macros, compilation), react-intl (ICU parser at runtime, untyped keys), Paraglide (its own compiler and format). Versions, React 19 support and size are from memory, **not verified**: check on npm in the first hour and record in ADR-0005; if it does not hold up, use react-intl. The language is determined by Rust from the system's preferred languages, not by `navigator.language` (in WKWebView it probably depends on the bundle's localizations; not verified). Dates and numbers use `Intl` in that language (day labels, time, the counter «12 тыс.» / “12K” with truncation, not rounding); the hard-coded month list in `dates.ts` is removed. Rust returns error codes; the texts live in the frontend.
- **Tab in WKWebView:** check in the real window; if buttons and links are skipped, make them reachable without the macOS system setting (DoD §12.2); the method goes in the PR.

## What “done” looks like
A 1280 × 800 window: the D1 «Главное окно» (“Main window”) screen on real data: a sidebar with a single Inbox (emoji, name, quiet counter) and the profile row, a ~720 px column, bubbles with the time, day labels; the input field shows only “Send” when there is text. An empty Inbox is the empty chat from D1. Settings uses new components (modal, a two-option choice, a path row with “Choose…”, status/error); the `design-system` agent builds them from tokens; stories: folder not selected / selected / error / long path, normal and large text, en and ru. Narrow window: everything is reachable, small flaws are acceptable.

## Checks

- Rust on SQLite: migration from scratch; a single Inbox after repeated starts; feed order and keyset; injected write failure: nothing written, an error code (§3.3); **a child process aborted (`abort`) right after commit: the data is in place**; `mirror_dirty` survives the abort, and the file appears at start; atomic file write; an unavailable folder.
- IPC (mock runtime): each command is available to `main` and not available to a window with another label; `open_external_url` rejects `file:`, `javascript:`, `data:`, `tauri:`, `asset:`, `ipc:`, a relative and an empty address; the JS commands of opener and dialog are unavailable; the `on_navigation` predicate.
- Frontend on `MockApi`: sending, Enter / Shift+Enter, neither a toast nor a confirmation after sending, an error keeps the text, Settings; Russian plurals for 0, 1, 2, 5, 11, 21, 22, 25, 111 and English; identical keys in `en.json` and `ru.json`; no Cyrillic in strings under `web/src` outside `locales`, demo data, stories and tests; day labels through `Intl` in en and ru. ## Touches sensitive areas
- **Schema: yes, `sync-crypto-guardian` before merge:** columns and group bytes, HLC, `sync_state`, the Inbox constant. Decision on ADR §C: only the tables slice 1 writes to are created; its rows carry everything ADR requires from the first entry (this cannot be fixed retroactively). The other tables would be empty until their slices, so a `CREATE TABLE` migration that does not change rows adds them: `tombstone` and `message_revision` in slice 3 (purge, revisions), `message_ext` in 4 (derived), `attachment` in 7, `change_outbox`, `quarantine`, `pending_unknown` in 11 (before binding the outbox is not written, ADR §6.2). The guardian confirms that in substance this is not a deviation from the ADR; §C is clarified.
- IPC: yes: new commands, capability, opener, dialog, `on_navigation`, negative tests. Encryption and sync: no.
- New dependencies (rusqlite, uuid, tauri-plugin-opener, tauri-plugin-dialog, i18next, react-i18next) are in the PR; the i18n choice is ADR-0005.

## User decisions (21.10.2026)
1. The Markdown copy is **on by default** in `~/Documents/Kinige`: a backup from the first entry; the folder can be changed in Settings. A macOS prompt for access to “Documents” is acceptable.
2. ~~“Undo” after sending puts the entry's text back in the input field so it can be fixed and sent again.~~ **Reversed by the user on 21.10.2026 after looking at the window:** the toast reserved space at the bottom of the feed and the last bubble jumped (“kindergarten design”). After sending, the entry simply appears in the feed, without a toast; the command, the code and the “Undo after sending” strings are removed; the toast component stays in the design system for slice 3 (“entry deleted — Undo”). Undoing a send is replaced by deleting and editing from the hover actions (slice 3).
3. Do not split: one slice of 6 days.

- **Slice 3 (delete, edit: the first rewrite of a single group):** bring back the tests removed together with send undo (commit `30969d0`, `set_deleted`): an unknown group of a newer version (`sv: 2`, whitespace in the bytes) and extra `hlc_json` fields survive a rewrite of another group verbatim; only the own group is rewritten, and it gets a new HLC strictly greater than the previous ones; broken JSON and a missing group are errors; a failed write changes nothing; the path “delete → counter → error by code” through IPC.
