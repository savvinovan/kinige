# Слайс 1: Inbox — первая настоящая запись

Бюджет: 6 дней, одним слайсом (решение пользователя 21.10.2026; старт — 21.10.2026 19:47 МСК, фактическое время записать при приёмке). Зависит от: D1, ADR-0001, ADR-0004 (приняты). Источники: ТЗ §2.1, §3.2, §4, §5, §6, §12.3, §15; ADR-0001 §1–§4, приложение §A.0, §C; `docs/screens/D1/README.md` («Открытые вопросы к слайсу 1»).

## Сценарий
1. Запускаю собранный Kinige на чистой машине: в сайдбаре один чат Inbox, лента пустая, курсор в поле ввода. Система на русском — интерфейс русский, на любом другом языке — английский.
2. Пишу «Купить **молоко**», Shift+Enter, «- [ ] позвонить маме», Enter. Меньше чем через 100 мс запись внизу ленты под меткой «Сегодня»: Markdown свёрстан, время у записи, счётчик Inbox — 1. Никакого тоста и подтверждения: запись просто появилась (изменено пользователем 21.10.2026 после просмотра окна; раньше здесь был тост «Отменить»).
3. Отправляю вторую запись: она так же просто появляется под первой, счётчик — 2. Отмены отправки нет: запись убирают удалением и правят редактированием из действий по наведению (слайс 3). (Прежний п. 3 — «Отменить» возвращает текст в поле — снят.)
4. Щёлкаю по ссылке `https://example.com` в записи: она открывается в системном браузере, окно Kinige на месте. Правый щелчок → «Open Link» тоже не уводит окно.
5. `kill -9`, запускаю снова: записи на месте, порядок и время те же.
6. Копия включена с первой записи в `~/Documents/Kinige`. Профиль → «Настройки»: вижу папку копии и предупреждение «копия — открытый текст», могу выбрать другую папку. В Finder — `Kinige/Inbox/2026/2026-10-21.md` с записями и временем; новая отправка обновляет файл за секунды, а если процесс убит сразу после отправки — при следующем запуске. «Размер текста» → «Крупный»: крупнее сразу и после перезапуска.
7. Прохожу настоящее окно клавишей Tab: фокус попадает на каждую кнопку, ссылку и пункт меню.

## Входит
- **Хранилище** `crates/kinige-store` (rusqlite, один поток-писатель, WAL, §3.2). Миграция 1: `chat`, `message` со всеми колонками §4.2 и ADR §C (`hlc_json` с `sv` по группам, `server_known`, `groups_raw`, `origin`, `ext_json`; `base`/`supersedes` внутри групп); `sync_state` (`device_id`, `hlc_l`, `hlc_c`); локальные несинхронизируемые `app_setting` и `mirror_dirty(chat_id, journal_date)`. Inbox — константный id и константная `core` (ADR §3.6), создаётся идемпотентно при первом старте; значение константы дописывается в приложение ADR-0001; хранимое имя пустое, интерфейс показывает переведённое.
- **`kinige-domain`** (без IO, wasm32): HLC (ADR §2, с продолжением счётчика после перезапуска), канонические байты групп JCS (ADR §3.3), новая запись сразу со всеми пятью группами (§A.0) и `sv = 1`, `journal_date` с границей дня 04:00 (§4.1), проверка схемы ссылки (только `http`, `https`, `mailto`).
- **Отправка (§5):** команда → одна транзакция (сообщение + HLC в `sync_state` + `mirror_dirty`) → ответ → запись в ленте. Без оптимистичного показа: при ошибке записи текст остаётся в поле, над ним ошибка (состояние D1). Успех — без тоста и без другой обратной связи. Отмены отправки нет (решение «Отменить» отменено пользователем 21.10.2026, см. ниже); группа `deleted` и корзина — слайс 3.
- **Главное окно на `TauriApi`** вместо временного экрана D1: Inbox с настоящим счётчиком; лента по `(journal_date, created_at, id)` — последняя страница по keyset-курсору из Rust, метки дней по `journal_date`; поле ввода (Enter, Shift+Enter, Enter в блоке кода); тост. Кнопок «файл», «эмодзи», «микрофон» в приложении нет — мёртвых кнопок нет (§5); в Storybook остаются. Ряд действий по наведению — как в D1. `MockApi` реализует тот же `KinigeApi` в памяти; типы `Demo*` заменяются сгенерированными (ADR-0002).
- **Markdown-копия (§2.1):** после commit фоновая задача целиком переписывает файл дня `Kinige/<чат>/YYYY/YYYY-MM-DD.md` (временный файл + rename); без корзины (§16); день без записей — файл удаляется; оставшиеся отметки обрабатываются при старте. Папка Inbox — `Inbox` при любом языке (путь не меняется от языка). Формат не зависит от языка (дата ISO, время 24 ч); заголовки внутри записей не ломают структуру. Недоступная папка — ошибка в настройках, отметки не теряются, повтор.
- **Настройки** — модальное окно внутри главного (без второго окна и своей capability), вход из меню профиля: папка копии (системный диалог вызывается из Rust, путь, статус, предупреждение «открытый текст», §12.3) и «Размер текста»: «Обычный» / «Крупный» ×1,25 (ADR-0004). Хранятся в `app_setting`, не синхронизируются. «Экспорт» и «О программе» остаются «Появится позже».
- **Ссылки (§6, §12.3):** команда `open_external_url` — схема проверяется в `kinige-domain`, открытие через `tauri-plugin-opener` только из Rust (JS-разрешений плагина у окна нет). `on_navigation` (`plugin::Builder::on_navigation`, есть в tauri 2.12.4) пускает только адрес приложения — закрывает «Open Link». Capability главного окна перечисляет только команды слайса (§12.3).
- **i18n:** все строки интерфейса, включая строки D1 (поле ввода, меню профиля, «Появится позже», «Сегодня»/«Вчера», ошибки, подписи для диктора), — в `web/src/locales/en.json` и `ru.json`. Библиотека **i18next + react-i18next**: склонение через встроенный `Intl.PluralRules` (CLDR, для ru — one/few/many/other); без макросов и шага компиляции (Vite 8, Storybook 10, Vitest 5 не трогаем); ключи типизированы по `en.json` (нет ключа — ошибка `tsc`); переводы в бандле, инициализация синхронная. Отклонены Lingui (макросы, компиляция), react-intl (ICU-парсер в рантайме, ключи без типов), Paraglide (свой компилятор и формат). Версии, поддержка React 19 и размер — по памяти, **не проверено**: сверить на npm в первый час, записать в ADR-0005; не подтвердится — react-intl. Язык определяет Rust по предпочитаемым языкам системы, а не `navigator.language` (в WKWebView он, вероятно, зависит от локализаций бандла — не проверено). Даты и числа — `Intl` на этом языке (метки дней, время, счётчик «12 тыс.» / «12K» с отбрасыванием, а не округлением); жёсткий список месяцев из `dates.ts` удаляется. Rust возвращает коды ошибок, тексты — во фронтенде.
- **Tab в WKWebView:** проверить в настоящем окне; если кнопки и ссылки пропускаются — сделать их доступными без системной настройки macOS (DoD §12.2), способ — в PR.

## НЕ входит
- Слайс 3: другие чаты, эмодзи, разделы сайдбара, контекстное меню, редактирование и ревизии, корзина, восстановление, purge, смена даты, теги, копия базы и проверка целостности.
- Слайс 2: окно захвата, хоткеи, трей, single-instance, матрица IPC второго окна. Черновик, переживающий перезапуск (§5), в §15 не назначен — предлагаю слайс 2, вместе с Esc окна захвата.
- Слайс 4: поиск, FTS, `body_search`, импорт, `message_ext`. Слайс 8 / S2: дозагрузка старых страниц, виртуализация, плавающая дата, переход к дате, позиция прокрутки.
- Вложения, эмодзи-пикер, голосовые (3, 7, 7a); переключатель языка и границы дня; перевод системного меню macOS; синхронизация и второй экземпляр `device_id` в Keychain (ADR §1, S4a).

## Как выглядит «готово»
Окно 1280 × 800 — экран «Главное окно» D1 на настоящих данных: сайдбар с одним Inbox (эмодзи, имя, тихий счётчик) и строкой профиля, колонка ~720 px, плашки с временем, метки дней; в поле ввода только «Отправить» при тексте. Пустой Inbox — пустой чат из D1. Настройки — новые компоненты (модальное окно, выбор из двух, строка пути с «Выбрать…», статус/ошибка), их делает агент `design-system` из токенов; истории: папка не выбрана / выбрана / ошибка / длинный путь, обычный и крупный текст, en и ru. Узкое окно: всё доступно, мелкие недочёты допустимы.

## Проверки
- Rust unit: HLC (локальное событие, переполнение счётчика, перезапуск), тест-векторы JCS, байты групп новой записи, `journal_date` у 04:00 и при переходе на летнее время.
- Rust на SQLite: миграция с нуля; Inbox один после повторных стартов; порядок ленты и keyset; инъекция отказа записи — ничего не записано, код ошибки (§3.3); **дочерний процесс прерван (`abort`) сразу после commit — данные на месте**; `mirror_dirty` переживает прерывание, файл появляется при старте; атомарная запись файла; недоступная папка.
- IPC (mock-рантайм): каждая команда доступна `main` и недоступна окну с другой меткой; `open_external_url` отвергает `file:`, `javascript:`, `data:`, `tauri:`, `asset:`, `ipc:`, относительный и пустой адрес; JS-команды opener и dialog недоступны; предикат `on_navigation`.
- Фронтенд на `MockApi`: отправка, Enter / Shift+Enter, ни тоста, ни подтверждения после отправки, ошибка оставляет текст, настройки; склонение ru для 0, 1, 2, 5, 11, 21, 22, 25, 111 и en; одинаковые ключи в `en.json` и `ru.json`; нет кириллицы в строках `web/src` вне `locales`, демо-данных, историй и тестов; метки дней через `Intl` в en и ru. Визуальные снимки новых компонентов и «Главного окна»: en и ru, обычный и крупный текст.
- Скриншоты `docs/screens/1/` (настоящее окно, скриптом): пустой Inbox; после отправки; после `kill -9` и перезапуска; крупный текст; настройки (не выбрана / выбрана / ошибка); английский интерфейс; узкое окно. Рядом: `ls -R` папки копии, файл дня, вывод тестов, холодный старт (< 1,5 с).

## Затрагивает чувствительные зоны
- **Схема — да, `sync-crypto-guardian` до мержа:** колонки и байты групп, HLC, `sync_state`, константа Inbox. Решение по ADR §C: создаются только таблицы, в которые слайс 1 пишет; его строки с первой записи несут всё, что требует ADR (задним числом их не исправить). Остальные до своих слайсов были бы пусты, поэтому их добавит миграция `CREATE TABLE` без изменения строк: `tombstone` и `message_revision` — слайс 3 (purge, ревизии), `message_ext` — 4 (производный), `attachment` — 7, `change_outbox`, `quarantine`, `pending_unknown` — 11 (до привязки outbox не пишется, ADR §6.2). Guardian подтверждает, что по существу это не отступление от ADR; §C уточняется.
- IPC — да: новые команды, capability, opener, dialog, `on_navigation`, отрицательные тесты. Шифрование и синхронизация — нет.
- Новые зависимости (rusqlite, uuid, tauri-plugin-opener, tauri-plugin-dialog, i18next, react-i18next) — в PR; выбор i18n — ADR-0005.
