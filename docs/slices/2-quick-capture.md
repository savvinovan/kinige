# Слайс 2: Быстрый захват — хоткей, окно захвата, хоткей буфера, трей

Бюджет: **~4 ч до готовности к приёмке** (реализация ~2,5 ч, включая смену сочетаний), **~9 ч до влития**; старт — 22.10.2026 02:45 МСК; без готовности к приёмке через 6 ч — стоп и доклад (§12.1a). Калибровка — факт слайса 1 (51 мин / 1 ч 36 мин / 6 ч 43 мин); данных меньше, чем в слайсе 1, но больше платформенного риска (фокус окон macOS, хоткей, трей). Зависит от: слайс 1 (влит). Источники: ТЗ §1.1, §2.1, §3.2, §5, §5.1, §9.3, §12.3, §15; ADR-0001 §3.3, §3.4, §4, приложение §A.0; `docs/slices/1-inbox.md` («НЕ входит», «Заметки для следующих слайсов»).

## Сценарий
1. Kinige запущен, главное окно закрыто крестиком: приложение работает, в menu bar его иконка. Я в браузере, нажимаю **⌥Space**: поверх всех окон, на экране с курсором, появляется маленькое окно — над полем бледно три последние записи Inbox за сегодня, курсор в поле. Главное окно не всплывает.
2. Пишу «Идея: …», Enter: окно исчезает, фокус снова в браузере. Открываю Kinige: запись внизу Inbox, счётчик +1, Markdown-копия обновилась. Если главное окно было открыто, запись появилась в нём сразу.
3. Через 3 минуты снова ⌥Space: последняя запись в контексте отмечена тихой подсказкой «⌘Enter — дописать». Пишу «и ещё», ⌘Enter: в ленте та же плашка с тем же временем, текст продолжается новым абзацем; новой записи нет.
4. Через 15 минут ⌘Enter: подсказки нет, получается новая запись (то же при пустом Inbox за сегодня и если последняя запись не моя, `origin ≠ 'user'`, §9.3).
5. Пишу в окне, жму Esc (или щёлкаю в другое окно): окно скрыто. ⌥Space — текст на месте. `kill -9`, запуск, ⌥Space — текст на месте. То же для поля ввода главного окна (§5).
6. Копирую текст в любой программе, жму хоткей буфера: окна нет, текст — новой записью в Inbox.
7. Иконка в menu bar → меню: «Новая заметка» (окно захвата), «Inbox» (главное окно), «Выйти». Повторный запуск приложения открывает существующее главное окно.
8. Сочетание занято другой программой — в «Настройках» видно, какое не назначено и почему; остальное работает.

## Входит
- **Окно `capture`** — отдельное окно Tauri, создаётся скрытым при старте (показ мгновенный; холодный старт перемерить, < 1,5 с): без заголовка, поверх всех окон, на всех рабочих столах, на экране с курсором. Хоткей при открытом окне его прячет; потеря фокуса — тоже (с черновиком). Если до показа активно было другое приложение, при скрытии фокус возвращается ему (`AppHandle::hide`), иначе прячется только окно захвата.
- **«Контекст»** = до 3 последних неудалённых записей Inbox с `journal_date` сегодня (§2.1, §12.3), Markdown свёрстан, длинные обрезаны по строкам; ссылки не открываются (у окна нет `open_external_url`).
- **Enter** — новая запись в Inbox (тот же путь, что `send_message`, `origin = 'user'`). **⌘Enter** — правило решает Rust в той же транзакции: последняя неудалённая запись Inbox, `origin = 'user'`, `created_at` не старше 10 мин (§2.1), все группы в поддерживаемой `sv` (ADR §4 п. 4) → дописать; иначе — новая запись. Ответ сообщает, что сделано.
- **Дописывание — первая перезапись группы:** `body_md = старый + "\n\n" + новый` (новый абзац; `breaks: true` склеил бы строки), лимит 512 КиБ по байтам группы; `edited_at` = сейчас; новый HLC строго больше прежних; `base`/`supersedes` по ADR §3.4 (своя неподтверждённая: `base = V.base`, `supersedes = V.supersedes ∪ {hlc(V)}`, ≤ 64; ветка `server_known = 1` тоже, с тестом). Остальные группы, неизвестные группы и неизвестные поля `body` — дословно (ADR §4 п. 1). Ревизии `edit` нет: старый текст — префикс нового, ничего не теряется; таблица ревизий — слайс 3. `mirror_dirty` дня записи.
- **Хоткей буфера:** текст из буфера (`arboard`, только из Rust) → нормализация → новая запись в Inbox. Не текст или пусто — ничего не пишется; сбой записи — открывается окно захвата с текстом буфера в поле и ошибкой (§1.2 п. 9). При успехе — короткое мигание иконки в menu bar (решение 2).
- **Черновики** (§5, §5.1): локальная несинхронизируемая таблица `draft(key, body, updated_at)` (миграция 2), ключи — окно захвата и чат главного окна; сохраняются с задержкой ~300 мс и при скрытии; очищаются в транзакции отправки. В Markdown-копию не попадают.
- **Трей** (ядро Tauri, фича `tray-icon`): монохромная template-иконка, меню из сценария; строки — из `web/src/locales/{en,ru}.json` (`include_str!`, один источник). «Последние чаты» = Inbox, пока других нет.
- **Жизненный цикл:** закрытие главного окна прячет его, приложение живёт; клик по Dock и второй запуск (`tauri-plugin-single-instance`) показывают его; ⌘Q и «Выйти» завершают.
- **IPC (§12.3):** `capability capture` — только `capture_state` (язык, размер текста, контекст, есть ли цель дописывания, черновик), `capture_send(body)`, `capture_append(body)` — без `chat_id`, только Inbox, `capture_save_draft(body)`, `capture_hide`. Главному — `get_draft`/`save_draft` и `core:event:allow-listen`/`unlisten` для события «записи изменились» (Rust шлёт только в `main`). §12.3 в PR дополняется «свой черновик и скрыть своё окно».
- **Настройки:** раздел «Сочетания клавиш» — два сочетания со статусом (назначено / занято), смена своего сочетания нажатием, сброс к умолчанию (решение 1).
- **Компоненты** (агент `design-system`, только токены): окно захвата, бледная запись контекста, подсказка дописывания, строка сочетания в настройках, иконка трея.

## НЕ входит
- Автозапуск при входе в систему (в ТЗ нет).
- Выбор чата в окне захвата, ⌘Enter в главном окне, правка и удаление из захвата, «последние чаты» кроме Inbox (слайс 3).
- Картинки и файлы из буфера, drag & drop на Dock (слайс 7); Windows/Linux, Wayland-запасной путь (§12.3, слайс 10); MCP-дописывание агента (4a).

## Как выглядит «готово»
Окно захвата ~560 px шириной (точно — дизайн-система): сверху до трёх бледных плашек контекста со временем, под ними поле как composer D1 без кнопок «файл/эмодзи/микрофон»; у последней плашки — подсказка «⌘Enter — дописать», когда есть цель. Ни тостов, ни подтверждений; контент не прыгает при появлении подсказки или ошибки (место под ошибку — над полем, как в D1). Истории: пусто за сегодня, 1 и 3 записи, длинные записи, длинный текст в поле, есть/нет цели, ошибка; en и ru; обычный и крупный текст. Узкое и крупное — без поломок, мелкие недочёты допустимы.

## Проверки
- Rust (domain): правило цели (граница 10 мин, `origin`, удалённая, вчерашняя, `sv` > 1); байты новой группы `body` для обеих веток §3.4; лимит после склейки; 64 в `supersedes`.
- Rust (SQLite): возвращённые тесты из «Заметок» слайса 1 — неизвестная группа (`sv: 2`, пробелы в байтах) и лишние поля `hlc_json` переживают дописывание дословно, меняется только `body`, HLC растёт, повреждённый JSON — ошибка, инъекция отказа — ничего не изменено; `abort` после commit дописывания и после сохранения черновика — данные на месте; миграция 1 → 2.
- IPC (mock): окно `capture` вызывает только свои пять команд; отказ в `list_messages`, `list_chats`, `send_message`, `get_settings`, `choose_mirror_folder`, `open_external_url`, `get_draft`, `core:event`, командах плагинов; `main` не вызывает `capture_*`.
- Фронтенд на `MockApi`: Enter, ⌘Enter (дописал / новая), Esc сохраняет черновик, ошибка оставляет текст, событие обновляет ленту главного окна, ключи en = ru.
- Скриншоты `docs/screens/2/` (скрипт снимает окно захвата отдельно — оно не на нулевом слое): окно над чужой программой; с контекстом и подсказкой; после ⌘Enter в ленте; черновик после `kill -9`; меню трея; настройки со статусом; en и крупный текст. Плюс вывод тестов и холодный старт.

## Затрагивает чувствительные зоны
- **Схема — да, `sync-crypto-guardian` до мержа:** первая перезапись группы (`body`, `base`/`supersedes`, HLC, сохранение неизвестного), отказ от ревизии `edit` при дописывании, миграция 2 (`draft`, локальная).
- **IPC — да:** второе окно и его capability, событие главному окну, отрицательные тесты. Шифрование и синхронизация — нет.
- Зависимости (в PR): фича `tray-icon` у `tauri` 2.12.4 — проверено по исходникам; `AppHandle::hide`, `visible_on_all_workspaces`, `always_on_top` в 2.12.4 — проверено; `arboard` 3.7 (`get_text`) — проверено; `tauri-plugin-global-shortcut` 2.4.1 и `tauri-plugin-single-instance` 2.5.4 — последние версии на crates.io (проверено 22.10.2026; совместимость с tauri 2.12.4 — сверить при подключении). По памяти, **не проверено**: хоткей на macOS идёт через Carbon `RegisterEventHotKey` без разрешения «Универсальный доступ»; если на чистой машине macOS спросит доступ (к хоткею или к буферу на macOS 26) — стоп и вопрос. Если при показе окна захвата всплывает главное окно — способ исправить (например, NSPanel; крейт не проверен) приносится в PR отдельным решением.

## Решения пользователя (22.10.2026)
1. **Сочетания по умолчанию:** захват — ⌥Space (как в ТЗ), буфер — ⌥⇧V. **Свои сочетания задаются в настройках уже в этом слайсе** (+~1 ч к бюджету): запись нового сочетания нажатием, проверка «занято» до сохранения, сброс к умолчанию; хранится в `app_setting`, не синхронизируется.
2. **Хоткей буфера при успехе:** короткое мигание иконки в menu bar (без звука и без окна). При сбое — окно захвата с текстом буфера и ошибкой, как выше.

## Факт (22.10.2026)
Старт 02:45 МСК; реализация и проверка на живых окнах — около 2,5 часов, готовность к приёмке — около 05:10 МСК (≈ 2 ч 25 мин). Доказательства — `docs/screens/2/` (README-карта, журнал прогонов, тесты, холодный старт), решения — ADR-0006, ТЗ v0.10.

**Отступления от спецификации:**
1. **Окно захвата на macOS — панель NSPanel без активации приложения** (`tauri-nspanel` 2.1.1, флаг `macOSPrivateApi`), а не обычное окно. Обычное окно в живом проверке работало ненадёжно: при чужой активной программе (Finder, оверлей стороннего ассистента) система снимала с него ключевой статус сразу после показа, и клавиши не доходили до страницы. Спецификация предлагала NSPanel «отдельным решением»; решение принято по результатам проверки и остаётся на подтверждение пользователя, откат — один коммит (ADR-0006). Побочный выигрыш: главное окно не всплывает, `AppHandle::hide` не нужен, прежняя программа сама остаётся активной.
2. Главному окну добавлены `set_shortcut`, `reset_shortcut`, `shortcut_recording` (а `get_settings` возвращает сочетания с состоянием): без них раздел «Сочетания клавиш» не работает; в «Входит» была только «смена в настройках». Окну захвата — ровно пять команд из спецификации.
3. **«Занято другой программой» на macOS не определяется:** `RegisterEventHotKey` успешно регистрирует даже ⌘Space, ⌘Tab и сочетания, занятые другим процессом (проверено из отдельного процесса, 12 сочетаний). Состояние «не назначено» работает (данные, интерфейс, тесты), но в живом окне получить его нечем. **Решение (22.10.2026): отложено**, в этом слайсе обнаружения занятости нет; вариант на будущее — проверять системные сочетания через `CopySymbolicHotKeys` (чужие программы всё равно не видны). Заметка для слайса 10: на Windows (`RegisterHotKey`) и Linux (X11 `XGrabKey`) занятость определяется самой системой.
4. Мигание значка в menu bar проверено по журналу (метка `flash` при `KINIGE_TRACE=1`), кадр мигания не снят.
5. Не проверено: окно над полноэкранной программой и на другом рабочем столе (флаги панели выставлены), ⌘V внутри панели, доступ к буферу в macOS 26 запросов не вызывал.

## Заметки для следующих слайсов
- **Слайс 3:** миграция 2 применяется к существующей базе без копии (копия перед миграцией — задача слайса 3, §10.4); хелпер тестов `mark_deleted` ставит `deleted` согласованно (колонка, группа, HLC), но не является настоящей операцией удаления — заменить; ревизии `edit` не создаются при дописывании (старый текст — префикс нового) — при появлении ревизий правки решить, нужна ли ревизия для дописывания; выбор чата в окне захвата; «последние чаты» в меню значка.
- **Слайс 10:** на Windows и Linux окно захвата — обычное окно (`show` + `set_focus`, блок `#[cfg(not(target_os = "macos"))]` в `capture.rs`); `RunEvent::Reopen` только на macOS.
- **Слайс 11 (синхронизация):**
  - Перезапись `body` пишет `base`/`supersedes` как в ADR §3.4; ревизии `conflict` и подтверждение сервером покрыты тестами только на уровне записи, не слияния.
  - Ветку `base`/`supersedes` выбирает флаг `CurrentBody::body_confirmed`; сейчас вызывающий берёт его из колонки `server_known`, а ADR §3.4 определяет неподтверждённую версию как «строка outbox без `acked_seq` **или** `server_known = 0»: когда появится outbox, учитывать оба признака.
  - Новый HLC не больше прежнего (`GroupError::HlcNotNewer`) сейчас приходит как `Internal`: при чужой метке дальше `SKEW_MAX` нужны внятная ошибка или новая запись вместо дописывания (часы только продолжаются, сверки с физическим временем ещё нет).
  - Источник старого текста при дописывании — сейчас колонка `body_md`; когда появится «миграция при чтении» (ADR §4 п. 3), брать текст из группы `body` (байты — источник правды, колонки — их разбор).
