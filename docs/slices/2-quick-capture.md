# Slice 2: Quick capture: hotkey, capture window, clipboard hotkey, tray

Budget: **~4 h until ready for acceptance** (implementation ~2.5 h, including changing shortcuts), **~9 h until merge**; started 22.10.2026 02:45 MSK; if not ready for acceptance after 6 h, stop and report (§12.1a). Calibration is the actual time of slice 1 (51 min / 1 h 36 min / 6 h 43 min); less data than in slice 1, but more platform risk (macOS window focus, hotkey, tray). Depends on: slice 1 (merged). Sources: PRD §1.1, §2.1, §3.2, §5, §5.1, §9.3, §12.3, §15; ADR-0001 §3.3, §3.4, §4, appendix §A.0; `docs/slices/1-inbox.md` (“Not included”, “Notes for the following slices”).

## Scenario
1. Kinige is running, the main window is closed with the close button: the app keeps running, its icon is in the menu bar. I am in a browser and press **⌥Space**: on top of all windows, on the screen with the pointer (at the bottom of the screen, centered: “Actual” item 7), a small window appears: above the field, faintly, the three latest Inbox entries of today, the cursor in the field. The main window does not pop up.
2. I type «Идея: …» (“Idea: …”), Enter: the window disappears, focus is back in the browser. I open Kinige: the entry is at the bottom of Inbox, the counter is +1, the Markdown copy is updated. If the main window was open, the entry appeared in it immediately.
3. 3 minutes later, ⌥Space again: the latest entry in the context is marked with a quiet hint “⌘Enter — append”. I type «и ещё» (“and also”), ⌘Enter: in the feed it is the same bubble with the same time, and the text continues in a new paragraph; there is no new entry.
4. 15 minutes later, ⌘Enter: no hint, and a new entry is created (the same happens when Inbox has nothing for today and when the latest entry is not mine, `origin ≠ 'user'`, §9.3).
5. I type in the window and press Esc (or click into another window): the window is hidden. ⌥Space: the text is still there. `kill -9`, launch, ⌥Space: the text is still there. The same goes for the input field of the main window (§5).
6. I copy text in any app and press the clipboard hotkey: no window, and the text becomes a new entry in Inbox.
7. Menu bar icon → menu: “New note” (capture window), “Inbox” (main window), “Quit Kinige”. Launching the app again opens the existing main window.
8. A shortcut is taken by another app: “Settings” shows which one is not assigned and why; everything else works.

## Included
- **The `capture` window** is a separate Tauri window, created hidden at start (showing is instant; re-measure cold start, < 1.5 s): no title bar, on top of all windows, on all desktops, on the screen with the pointer. The hotkey hides it while it is open; losing focus does too (keeping the draft). If another app was active before it was shown, focus returns to that app on hide (`AppHandle::hide`); otherwise only the capture window is hidden.
- **“Context”** = up to 3 latest non-deleted Inbox entries with today's `journal_date` (§2.1, §12.3), Markdown rendered, long ones cut by lines; links do not open (the window has no `open_external_url`).
- **Enter** creates a new entry in Inbox (the same path as `send_message`, `origin = 'user'`). **⌘Enter**: Rust decides the rule in the same transaction: the latest non-deleted Inbox entry, `origin = 'user'`, `created_at` no older than 10 min (§2.1), all groups in a supported `sv` (ADR §4 item 4) → append; otherwise a new entry. The response says what was done.
- **Appending is the first rewrite of a group:** `body_md = old + "\n\n" + new` (a new paragraph; `breaks: true` would glue the lines together), a 512 KiB limit on the group bytes; `edited_at` = now; a new HLC strictly greater than the previous ones; `base`/`supersedes` per ADR §3.4 (own unconfirmed: `base = V.base`, `supersedes = V.supersedes ∪ {hlc(V)}`, ≤ 64; the `server_known = 1` branch too, with a test). Other groups, unknown groups and unknown `body` fields are kept verbatim (ADR §4 item 1). No `edit` revision: the old text is a prefix of the new one, nothing is lost; the revision table is slice 3. `mirror_dirty` for the entry's day.
- **Clipboard hotkey:** text from the clipboard (`arboard`, from Rust only) → normalization → a new entry in Inbox. Not text or empty: nothing is written; a write failure opens the capture window with the clipboard text in the field and an error (§1.2 item 9). On success, a short flash of the menu bar icon (decision 2).
- **Drafts** (§5, §5.1): a local unsynced table `draft(key, body, updated_at)` (migration 2), keys are the capture window and the chat of the main window; saved with a delay of ~300 ms and on hide; cleared in the send transaction. They do not go into the Markdown copy.
- **Tray** (Tauri core, feature `tray-icon`): a monochrome template icon, the menu from the scenario; strings come from `web/src/locales/{en,ru}.json` (`include_str!`, one source). “Recent chats” = Inbox while there are no others.
- **Lifecycle:** closing the main window hides it, the app stays alive; a Dock click and a second launch (`tauri-plugin-single-instance`) show it; ⌘Q and “Quit Kinige” exit.
- **IPC (§12.3):** `capability capture`: only `capture_state` (language, text size, context, whether there is an append target, draft), `capture_send(body)`, `capture_append(body)` (no `chat_id`, Inbox only), `capture_save_draft(body)`, `capture_hide`. The main window gets `get_draft`/`save_draft` and `core:event:allow-listen`/`unlisten` for the “entries changed” event (Rust sends it only to `main`). In the PR, §12.3 is extended with “its own draft and hiding its own window”.
- **Settings:** a “Keyboard shortcuts” section with two shortcuts and their status (assigned / taken), changing a shortcut by pressing it, reset to default (decision 1).
- **Components** (the `design-system` agent, tokens only): capture window, faint context entry, append hint, shortcut row in Settings, tray icon.

## Not included
- Launch at login (not in the PRD).
- Choosing a chat in the capture window, ⌘Enter in the main window, editing and deleting from capture, “recent chats” other than Inbox (slice 3).
- Images and files from the clipboard, drag & drop onto the Dock (slice 7); Windows/Linux, the Wayland fallback (§12.3, slice 10); MCP append by an agent (4a).

## What “done” looks like
(The look was changed at acceptance, see “Actual” item 6: a rounded floating panel, height fits the content, the hint and the error below the field.) A capture window ~560 px wide (exact value from the design system): at the top, up to three faint context bubbles with the time, below them a field like the D1 composer without the “file/emoji/microphone” buttons; the last bubble has the hint “⌘Enter — append” when there is a target. No toasts, no confirmations; the content does not jump when the hint or an error appears (the space for the error is above the field, as in D1). Stories: nothing for today, 1 and 3 entries, long entries, long text in the field, with/without a target, error; en and ru; normal and large text. Narrow and large: nothing broken, small flaws are acceptable.

## Checks
- Rust (domain): the target rule (the 10 min boundary, `origin`, deleted, yesterday's, `sv` > 1); the bytes of the new `body` group for both branches of §3.4; the limit after concatenation; 64 in `supersedes`.
- Rust (SQLite): the tests returned from the slice 1 “Notes”: an unknown group (`sv: 2`, whitespace in the bytes) and extra `hlc_json` fields survive appending verbatim, only `body` changes, HLC grows, broken JSON is an error, injected failure: nothing changed; `abort` after the append commit and after saving a draft: the data is in place; migration 1 → 2.
- IPC (mock): the `capture` window calls only its own six commands (five plus `capture_resize`); denied for `list_messages`, `list_chats`, `send_message`, `get_settings`, `choose_mirror_folder`, `open_external_url`, `get_draft`, `core:event`, plugin commands; `main` does not call `capture_*`.
- Frontend on `MockApi`: Enter, ⌘Enter (appended / new), Esc saves the draft, an error keeps the text, the event updates the main window feed, en keys = ru keys.
- Screenshots in `docs/screens/2/` (the script captures the capture window separately, since it is not on layer zero): the window over another app; with context and the hint; after ⌘Enter in the feed; the draft after `kill -9`; the tray menu; Settings with status; en and large text. Plus test output and cold start.

## Touches sensitive areas

- **IPC: yes:** the second window and its capability, an event to the main window, negative tests. Encryption and sync: no.
- Dependencies (in the PR): feature `tray-icon` of `tauri` 2.12.4 (verified in the source); `AppHandle::hide`, `visible_on_all_workspaces`, `always_on_top` in 2.12.4 (verified); `arboard` 3.7 (`get_text`) (verified); `tauri-plugin-global-shortcut` 2.4.1 and `tauri-plugin-single-instance` 2.5.4 are the latest versions on crates.io (verified 22.10.2026; compatibility with tauri 2.12.4 to be checked when added). From memory, **not verified**: on macOS the hotkey goes through Carbon `RegisterEventHotKey` without the “Accessibility” («Универсальный доступ») permission; if macOS asks for access on a clean machine (for the hotkey, or for the clipboard on macOS 26), stop and ask. If the main window pops up when the capture window is shown, the fix (for example, NSPanel; the crate is not verified) comes in the PR as a separate decision.

## User decisions (22.10.2026)
1. **Default shortcuts:** capture is **temporarily ⌃⌥N: ⌥Space and ⌥⇧Space are taken by ChatGPT/Gemini, ⌃Space/⌃⌥Space switch the keyboard layout, ⌘Space is Raycast (22.10.2026)**. Clipboard is ⌥⇧V. In the scenario above, read “⌥Space” as “the capture shortcut” (⌃⌥N by default). **Custom shortcuts are set in Settings already in this slice** (+~1 h to the budget): recording a new shortcut by pressing it, a “taken” check before saving, reset to default; stored in `app_setting`, not synced.

**Deviations from the spec:**
1. **On macOS the capture window is an NSPanel that does not activate the app** (`tauri-nspanel` 2.1.1, the `macOSPrivateApi` flag), not a regular window. **Accepted by the product owner on 22.10.2026** (the Mac App Store is not planned; it behaves like Spotlight and Raycast): the main window does not pop up, `AppHandle::hide` is not needed, the previous app stays active by itself. The original reasoning “a regular window is unreliable because of macOS cooperative activation” is **not confirmed**: ⌥Space on the test machine is taken by ChatGPT, and the “loss of focus” during the check was most likely ChatGPT reacting (details in ADR-0006). Rollback is one commit.
2. The main window got `set_shortcut`, `reset_shortcut`, `shortcut_recording` (and `get_settings` returns the shortcuts with their state): without them the “Keyboard shortcuts” section does not work; “Included” only said “changing in Settings”. The capture window got the five commands from the spec and a sixth, `capture_resize` (window height fits the content; added after the user's remark at acceptance, see item 6).
3. **“Taken by another app” is not detected on macOS:** `RegisterEventHotKey` successfully registers even ⌘Space, ⌘Tab and shortcuts taken by another process (verified from a separate process, 12 shortcuts). The “not assigned” state works (data, UI, tests), but in the live window there is no way to get it. **Decision (22.10.2026): postponed**; this slice has no detection of taken shortcuts; an option for the future is checking system shortcuts through `CopySymbolicHotKeys` (other apps are still invisible). Note for slice 10: on Windows (`RegisterHotKey`) and Linux (X11 `XGrabKey`) the system itself reports a taken shortcut.
4. The flash of the menu bar icon was verified through the log (the `flash` mark with `KINIGE_TRACE=1`); a frame of the flash was not captured.
6. **The look of the capture window was changed at acceptance (22.10.2026).** The user: “too angular”, the main UI does not look like that; references are Gemini and ChatGPT. Instead of a rectangular 560 × 360 window with an empty area at the top, a transparent window with a floating rounded panel, height fits the content (one line when there are no entries), the “Send” field inside, the hint and the error below the field. New tokens: `radius.floating`, `opacity.panel-edge`, `layout.capture.panel-width / shadow-margin / window-min-height / window-max-height`; `window-width` 560 → 584, `window-height` 360 → 122 (initial). The string «Сегодня записей ещё нет» (“No entries today yet”) and the key `capture.empty` are removed. Details are in ADR-0006, section “Look”.
7. **The capture window sits at the bottom of the screen with the bottom edge pinned (acceptance 27.10.2026).** At 28% of the screen height from the top, the window covered what the person wanted to write about. Now the panel is centered at the bottom of the screen with the pointer: the bottom edge is 12% of the monitor work area height (without the Dock and the menu bar) above its bottom; the context and multi-line text grow upwards, and the input field always stays in one place. `capture_resize` pins the bottom edge, not the top. Details are in ADR-0006, section “Look”.
5. Not verified: the window over a full-screen app and on another desktop (the panel flags are set), ⌘V inside the panel; clipboard access on macOS 26 did not trigger any prompts.

## Notes for the following slices
- **Slice 3:** migration 2 is applied to an existing database without a backup (a pre-migration backup is a slice 3 task, §10.4); the test helper `mark_deleted` sets `deleted` consistently (column, group, HLC) but is not the real delete operation; replace it; `edit` revisions are not created on append (the old text is a prefix of the new one); when edit revisions arrive, decide whether append needs a revision; choosing a chat in the capture window; “recent chats” in the icon menu.
  - **Files over 400 lines** (project rule 6): `src-tauri/src/hotkeys.rs` (415; later split into `hotkeys/mod.rs` and `hotkeys/tests.rs`) and `src-tauri/tests/ipc.rs` (587; later split into `ipc*.rs`); split them on the next edits (for example, `hotkeys/` by state and by registration; `ipc.rs` into window ACL tests and tests of the capture and shortcut scenarios).
  - **An edge case from the guardian:** keystrokes typed less than 300 ms before a clipboard hotkey failure are not yet saved in the draft, while the clipboard failure builds the draft from the database (`merge_clipboard_into_capture_draft`) and opens the window with it; the unsaved tail may then be lost or diverge from what is in the field. Decide together with choosing a chat in the capture window: either the window asks the page to flush the draft (`flush`) before the failure, or Rust takes the text from the page.
- **Slice 10:** on Windows and Linux the capture window is a regular window (`show` + `set_focus`, the `#[cfg(not(target_os = "macos"))]` block in `capture.rs`); `RunEvent::Reopen` is macOS only.
- **Slice 11 (sync):**
  - The `body` rewrite writes `base`/`supersedes` as in ADR §3.4; `conflict` revisions and server confirmation are covered by tests only at the write level, not at the merge level.
  - The `base`/`supersedes` branch is chosen by the flag `CurrentBody::body_confirmed`; now the caller takes it from the `server_known` column, while ADR §3.4 defines an unconfirmed version as “an outbox row without `acked_seq` **or** `server_known = 0`”: once the outbox exists, take both into account.
  - A new HLC that is not greater than the previous one (`GroupError::HlcNotNewer`) now comes out as `Internal`: with a foreign timestamp beyond `SKEW_MAX`, a clear error or a new entry instead of an append is needed (the clock only continues, there is no comparison with physical time yet).
  - The source of the old text on append is now the `body_md` column; once “migration on read” exists (ADR §4 item 3), take the text from the `body` group (the bytes are the source of truth, the columns are their parsed form).
