# Слайс 4a: MCP-сервер `kinige-mcp` — агент читает журнал и добавляет записи

Бюджет: **~8 ч до готовности к приёмке, ~12 ч до влития**. Если через 16 ч готовности к приёмке нет — стоп и доклад (§12.1a).

Калибровка:
- слайс 3 сделан за 2 ч 20 мин при бюджете 8 ч;
- слайс 4 — за ≈ 2 ч 10 мин активной работы при бюджете ~12 ч.

Объём здесь — около 0,7 слайса 4. Внешний риск — крейт MCP и поведение настоящих клиентов. Ожидаемое время — 3–4 ч активной работы. Слайс не режется, PR один. Работа идёт в порядке «Задач»: если бюджет кончится, недоделанным останется журнал в интерфейсе, а не права доступа.

Зависит от: слайс 4 (принят 28.10.2026), ADR-0009 (предложено; принять до начала). Источники: ТЗ §1.2 п. 8, §2.1, §3.2, §4.1–4.2, §9.1, §9.3, §10, §12.2, §12.3, §15; ADR-0001 («origin», §2, §4, «Не решается»), ADR-0006 (правило дописывания), ADR-0008.

## Сценарий
1. Профиль → «Настройки» → строка «Доступ ИИ-агентов: выключен · Настроить…». Открывается окно «Доступ ИИ-агентов». Ставлю флажок «Разрешить агентам доступ к журналу». Появляется предупреждение: «Текст, который прочитает агент, уйдёт провайдеру его модели. Сквозное шифрование Kinige на это не распространяется». Кнопки «Включить» и «Отмена».
2. Ниже в окне:
   - режим «Только чтение / Чтение и запись»;
   - список чатов с флажками «видно агенту» (сразу отмечен только Inbox);
   - блок «Как подключить»: фрагмент JSON для Claude Desktop и команда для Claude Code, у каждого кнопка «Копировать».
3. Вставляю фрагмент в конфиг Claude Desktop и перезапускаю его. В списке инструментов клиента появляется `kinige`.
4. Спрашиваю «что я писал про Raft в марте?». Агент ищет и отвечает по записям только отмеченных чатов. Запись неотмеченного чата не находится ни поиском, ни по id.
5. «Запиши в Kinige итоги встречи: …». В режиме «чтение и запись» запись сразу появляется в Inbox открытого окна, у времени тихая пометка «добавлено агентом». «Добавь ещё пункт» в течение 10 минут дописывается к той же записи. В режиме «только чтение» агент получает отказ, ничего не записано.
6. «Отметь задачу „купить билеты“ выполненной» — флажок задачи отмечен (любой записи-задачи видимого чата).
7. В том же окне — «Журнал обращений», новые сверху. Примеры строк: «14:02 · Claude Desktop · поиск «Raft» · 3 записи», «14:05 · добавить запись · 1 запись», «14:06 · отказано: только чтение». Щелчок по строке раскрывает записи (чат, дата, начало текста). Щелчок по записи открывает её в ленте.
8. Снимаю флажок доступа. Следующий вызов агента получает «Доступ агентов выключен в Kinige», в журнале — «отказано».
9. Выхожу из Kinige (⌘Q) и снова спрашиваю агента. Kinige запускается в фоне (значок в menu bar, окна нет), агент получает ответ.
10. После записи агента делаю `kill -9` Kinige и запускаю снова. Запись, пометка и строки журнала на месте, в Markdown-копии дня есть запись.

## Входит
- **ADR-0009:** сервер MCP работает внутри приложения, `kinige-mcp` — мост stdio ↔ Unix-сокет, базу он не открывает.
- **Мост** — `crates/kinige-mcp`, только std. Попадает в бандл через `bundle.externalBin`.
- **Сервер MCP** в `src-tauri`, инструменты:
  - чтение: поиск, записи за день и за диапазон, «в этот день», список чатов, запись по id;
  - запись: новая запись в Inbox или в чат, дописать к своей последней записи, задача (по вопросу 4).
- **Права в Rust при каждом вызове:**
  - выключатель и режим;
  - разрешённые чаты; `ai_excluded` не видны никогда;
  - корзина и удалённые чаты не видны.
- **Хранилище:**
  - чтение в рамках разрешённых чатов;
  - записи с `origin = 'agent'`;
  - миграция 5: локальная таблица `mcp_log`;
  - настройки в `app_setting`;
  - обслуживание удаляет журнал старше 90 дней.
- **Лента:** пометка «добавлено агентом» (`MessageView.origin`).
- **Окно «Доступ ИИ-агентов»** и строка в «Настройках». Новые команды — только главному окну.
- **Запуск в фоне** (`--background`), если по вопросу 1 выбран вариант A.

## НЕ входит
- **Возможности MCP:**
  - семантический поиск (P1);
  - ресурсы и подсказки MCP, `structuredContent`, `tools/list_changed`;
  - HTTP, SSE и любой сетевой порт (§12.3).
- **Действия агента:** удаление, перенос, правка текста, смена даты, избранное (§9.3); дописывание к записям пользователя и импорта; вложения (слайс 7).
- **`ai_excluded`:** переключатель у чата не делается. Правило соблюдается в коде, а сам переключатель придёт с AI в P1, где он означает «не отправлять в OpenRouter». В этом слайсе чат закрывает от агента снятый флажок в списке.
- **Подключение клиентов:** конфиги Claude Desktop и Claude Code не правим автоматически — только фрагмент и «Копировать».
- **Пометка агента вне ленты:** её нет в Markdown-копии и в окне захвата; имени клиента нет в данных записи (оно есть только в журнале).
- **Журнал:** нет кнопки очистки и экспорта.
- **Платформы:** Windows и Linux — слайс 10.

## Как выглядит «готово»
**Окно «Доступ ИИ-агентов»** — `Modal` D1 поверх главного окна, 1280 × 800. Сверху вниз:
- флажок доступа (`Checkbox` слайса 4) с одной строкой пояснения;
- режим (`SegmentedChoice`);
- список чатов с флажками: эмодзи, имя (многоточие), число записей; высота списка ограничена токеном, прокрутка внутри;
- «Как подключить»: путь и фрагмент моноширинным шрифтом (JetBrains Mono) и кнопка «Копировать»;
- «Журнал обращений»: тихие строки «время · клиент · действие · N записей», подгрузка «Показать ещё».

Пока доступ выключен, режим и чаты неактивны, журнал виден. Пустой журнал — одна строка «Обращений не было». Ошибки:
- сокет недоступен (длинный путь, сбой `bind`) — строка ошибки D1;
- бинарник моста не найден рядом с приложением (сборка `dev`) — строка вместо фрагмента.

Предупреждение при включении — второй `Modal`. Тостов нет. Подтверждение при включении требует ТЗ §9.3, это не подтверждение рутинного действия.

**Пометка в ленте:** «добавлено агентом» стилем метаданных (`color.text.tertiary`, размер метки времени) в строке времени. Плашка не меняется, лента не прыгает.

Истории Storybook — каждое состояние окна и запись с пометкой: en и ru, обычный и крупный текст, длинные имена и запросы. В узком окне всё доступно.

## Проверки
- **Rust (domain):**
  - байты `core` с `"origin":"agent"` без `ext`, по JCS;
  - правило дописывания для агента;
  - даты «в этот день»;
  - проверка аргументов инструментов (лимиты, даты, формат id).
- **Rust (SQLite):**
  - миграция 4 → 5 с копией перед ней;
  - матрица «инструмент × чат». Чат не разрешён, с `ai_excluded`, удалён; запись в корзине. Такие записи и чаты не видны ни в поиске, ни по id, ни за день или диапазон, ни в «этот день», ни в списке чатов. Ответ — тот же `not_found`, что для несуществующего;
  - «только чтение» и «выключено» отказывают, ничего не записано;
  - каждый вызов, успешный и отказанный, — ровно одна строка `mcp_log`;
  - запись и её строка журнала — одна транзакция: инъекция отказа на `mcp_log` → записи нет; `abort` после commit → запись и строка на месте;
  - дописывание идёт только к своей последней записи; окно захвата к записи агента не дописывает;
  - файлы Markdown-копии на месте;
  - журнал старше 90 дней удаляется.
- **Сервер MCP** (в процессе, по паре сокетов):
  - `initialize`, затем `tools/list` по режиму, затем вызовы;
  - два клиента одновременно;
  - событие «записи изменились» уходит главному окну.
- **Мост** (собранный бинарник в тесте):
  - пересылка в обе стороны;
  - нет сокета → ошибка JSON-RPC с тем же `id`;
  - после обрыва переподключается и повторяет `initialize`;
  - в stdout идёт только JSON-RPC.
- **IPC (mock):** новые команды разрешены `main` и отказаны `capture`; у окна захвата по-прежнему ровно семь команд.
- **Фронтенд на `MockApi`:**
  - окно: включение, отмена предупреждения, режим, чаты, «Копировать», журнал (раскрытие, открытие записи);
  - пометка в ленте;
  - ключи en и ru совпадают;
  - эталоны в Linux.
- **Скриншоты `docs/screens/4a/`** — снимает ревьюер на сборке с отдельным `identifier` и временным `KINIGE_DATA_DIR`. Конфиги Claude пользователя не трогаются.
  - Снимки: окно выключено; предупреждение; окно включено со списком и фрагментом; журнал раскрыт; лента с записью агента; отказ в журнале; en и крупный текст; после `kill -9`.
  - Рядом — протокол сеанса скриптом через `kinige-mcp` (запросы и ответы JSON). Если у Claude Code есть флаг `--mcp-config` (не проверено), то и сеанс с ним без правки конфигов.
  - Настоящий Claude Desktop проверяет пользователь при приёмке.

## Затрагивает чувствительные зоны
**`sync-crypto-guardian` до мержа:**
- доступ к данным: фильтр в каждом инструменте, отказ по id без раскрытия существования;
- байты `core` записи агента;
- как второй процесс пишет в базу: никак, только через писатель приложения (ADR-0009);
- миграция 5 и `mcp_log` в одной транзакции с изменением;
- права на папку сокета.

Это дописывается в приложение ADR-0001 как §C.4. **IPC — да.** Шифрование и протокол синхронизации — нет: записи агента уйдут в outbox слайса 11, как любые другие.

**Зависимости** (в PR): `rmcp` (проверка в задаче 4a.0), фича `net` у `tokio` (уже в дереве). У моста зависимостей нет.

## Технические решения (приняты здесь; возразить можно при приёмке спецификации)
1. **Где сервер.** По ADR-0009. Сокет — `<каталог данных>/mcp/kinige.sock`, права 0700, путь не длиннее 100 байт. Приложение слушает, пока журнал открыт. Если стоит отметка повреждения — ответ `journal_unavailable`.
2. **Мост.** Запускается как `kinige-mcp --socket <путь>`: путь подставляет фрагмент из окна, поэтому сборки с другим `identifier` и временный каталог данных работают сами. Мост запоминает `initialize` для переподключения. Диагностика — только в stderr.
3. **Инструменты** (имена и описания по-английски, ответ — текст с JSON):
   - `list_chats` — чаты: id, название (Inbox — на языке интерфейса), эмодзи, число записей, архив;
   - `search(query, chat_id?, from?, to?, favorites?, tasks?, cursor?)` — до 50 записей; FTS из ADR-0008 через `Store::search`, но только по разрешённым чатам;
   - `get_entries(date | from+to, chat_id?, cursor?)` — до 200 записей;
   - `on_this_day(date?)` — тот же месяц и день прошлых лет, 29 февраля только к 29 февраля. Функция в домене, её возьмёт слайс 5;
   - `get_entry(id)`;
   - `add_entry(text, chat_id?, task?)`;
   - `append_to_last_entry(text, chat_id?)`;
   - `set_task_done(id, done)`.

   В каждой записи: id, чат, `journal_date`, местное время с поясом, `origin`, флаги, текст. В выдаче списков текст обрезается до 2 000 знаков с признаком `truncated`, целиком — в `get_entry`. Ответ не больше 1 МиБ. Ошибки — `isError` с понятным текстом.
4. **Видимость:** чат виден ⇔ он в `mcp_chats`, у него нет `ai_excluded` и он не удалён; архив виден. Настройки читаются в каждом вызове: снятый флажок действует сразу.
5. **Запись** — те же операции, что у интерфейса:
   - `send` с происхождением `agent` (константа `ORIGIN_AGENT`), лимит текста тот же;
   - дописывание — правило ADR-0006 с `origin = 'agent'`: последняя живая запись чата, создана агентом, не старше 10 минут, сегодняшний день. Иначе отказ `no_agent_entry`, новая запись не создаётся. Ревизии нет;
   - задача — `set_message_flag`;
   - после записи — событие главному окну, `tray::refresh` и Markdown-копия.

   Даты агент не задаёт.
6. **Журнал** `mcp_log(id, at, client, tool, args_json, message_ids_json, outcome)`:
   - `args_json` обрезается до 512 знаков, id записей — не больше 200, дальше только счётчик;
   - изменение и его строка журнала — одна транзакция;
   - чтение пишет строку до ответа: не удалось записать — агент получает ошибку, а не данные.
7. **Настройки:** `mcp_enabled`, `mcp_mode` (`read` | `read_write`, по умолчанию `read`), `mcp_chats`. По умолчанию доступ выключен.
8. **Пометка о провайдере** — по ADR-0009: предупреждение в Kinige, `instructions`, описания, `readOnlyHint`.
8a. **Вызовы агента не открывают окон и диалогов.** Окно не выводится на передний план и не получает фокус, тосты не показываются. Открытая лента обновляется тихо. Всё, что требует решения пользователя, возвращается агенту ошибкой с понятным текстом. Сюда относятся выключенный доступ, режим «только чтение», закрытый чат, база в восстановлении. Тест: ни один инструмент не вызывает показ окна.
9. **Фрагменты подключения.** Абсолютный путь моста — `current_exe()` рядом. Claude Desktop: `{"mcpServers":{"kinige":{"command":"…/kinige-mcp","args":["--socket","…"]}}}`; путь к конфигу показывается по памяти (`~/Library/Application Support/Claude/claude_desktop_config.json`, не проверено). Claude Code: `claude mcp add kinige -- …/kinige-mcp --socket …`, синтаксис не проверен — сверить в 4a.0.

## Решения пользователя (28.10.2026)
1. **Kinige не запущен, а агент обратился** — мост сам запускает Kinige в фоне: значок в menu bar, окно не открывается, первый ответ через 1–3 с. Если запуск не удался за 10 с — ответ «Откройте Kinige».
2. **Видимость чатов после включения** — отмечен только Inbox; новые чаты закрыты, пока их не отметишь.
3. **Режим** — один переключатель «Только чтение / Чтение и запись»; писать можно в любой видимый чат.
4. **Задачи** — агент может отметить выполненной и снять отметку у любой записи-задачи видимого чата, а свою новую запись — сразу создать задачей. Чужую запись сделать задачей не может.

## Задачи
Общее: проверки из `CLAUDE.md` («Сборка и тесты»); только точечные правки (Edit/Write), без скриптов замены; файл не длиннее 400 строк; строки — только в `web/src/locales/{en,ru}.json`; визуал — только из токенов.

**4a.0. Проверка крейта и клиентов** — S, guardian: нет.
- **Что сделать:**
  - `rmcp`: версия, лицензия, дата релиза, сервер поверх `UnixStream`, отключаемые HTTP-фичи, сборка на нашем toolchain. Критерии отказа — в ADR-0009; при отказе — свой минимальный сервер;
  - текст спецификации MCP о stdio, `instructions` и аннотациях;
  - путь конфига Claude Desktop, синтаксис `claude mcp add`, флаг `--mcp-config`.
- **Готово, когда:** раздел «не проверено» ADR-0009 исправлен по фактам, ADR принят пользователем.

**4a.1. Домен** — S, guardian: **да**.
- **Что сделать:**
  - `ORIGIN_AGENT`; конструктор записи агента через общую сборку `groups`;
  - обобщить `append::can_append` по ожидаемому `origin` (поведение для `user` не меняется);
  - `on_this_day` по датам;
  - проверка аргументов инструментов.
- **Файлы:** `crates/kinige-domain/src/{groups,append}.rs`, новый `agent.rs` (+ тесты).
- **Готово, когда:** точные байты `core`, тесты `append` не изменились и проходят, wasm32 собирается.

**4a.2. Хранилище** — M, guardian: **да**.
- **Что сделать:**
  - `MIGRATION_5` (`mcp_log`) с копией перед ней;
  - настройки MCP;
  - `Store` для агента: видимые чаты, поиск, день, диапазон, «этот день» и запись по id в пределах видимых чатов; новая запись, дописывание и задача — каждое со строкой журнала в той же транзакции;
  - чтение журнала keyset-страницами;
  - очистка журнала в обслуживании;
  - `MessageView.origin`;
  - §C.4 в приложении ADR-0001.
- **Файлы:** `schema.rs`, новые `crates/kinige-store/src/{agent,agent_log}.rs`, `search_query.rs` (набор чатов), `maintenance.rs`, `view.rs`; тесты `crates/kinige-store/tests/agent*.rs`.
- **Готово, когда:** вся матрица видимости и отказов из «Проверок» и сценарии `abort` и инъекции отказа проходят.
- **Зависит от:** 4a.1.

**4a.3. Мост `kinige-mcp`** — S, guardian: нет.
- **Что сделать:**
  - пересылка строк stdin ↔ сокет, двумя потоками;
  - повтор `initialize` после переподключения;
  - запуск приложения по вопросу 1;
  - ошибки JSON-RPC с тем же `id`.
- **Файлы:** новый `crates/kinige-mcp/` (член workspace), тест `tests/bridge.rs` с подставным сервером на временном сокете.
- **Готово, когда:** тесты моста из «Проверок» проходят, бинарник собирается без зависимостей.

**4a.4. Сервер MCP в приложении** — M, guardian: **да** (доступ к данным).
- **Что сделать:**
  - слушатель сокета в `start_services`: папка 0700, предел длины пути, удаление старого файла;
  - сервер на `rmcp` (или свой по 4a.0) с инструментами из решения 3;
  - `clientInfo` в журнал;
  - `instructions` и `readOnlyHint`;
  - отказы `mcp_disabled`, `mcp_read_only`, `journal_unavailable`;
