# Slice D2: visual refresh of the app

Huly: KINIG-55. Depends on: D1 (ADR-0004), slices 1-5. Budget: 2 days. The user likes the rhythm of the sidebar of another app (a personal screenshot, not stored in the repository): roomy margins and paddings, a larger font, a rounded selected row with a soft fill, quiet small gray section headings with space above, tiles next to items, icons on the bottom items, a highlight on hover. We carry over the principles of rhythm, sizes and hierarchy; no logo, no name, no brand colors.

## Scenario
The user opens the app and sees the same screens as before, only calmer and roomier: the sidebar is wider, rows are taller, each chat has its emoji on the left (a chat without an emoji has a colored rounded square with the first letter of its title), the "Pinned" / "Chats" / "Archive" headings are quiet with space above, the selected chat is filled with a rounded plate, the row under the mouse is highlighted. At the bottom, "Trash" and the profile carry icons in the same rhythm. The feed, plates, day labels, the "On this day" card, quotes, the input field, the settings window, dialogs, the capture window, search, trash, recovery and import became larger and roomier by the same rules. No functions or texts were added.

## Included
- **Tokens** (`design/tokens/`, then `npm run tokens`): new and changed font sizes, radii, layout, fill and tile colors (table below). Components use only tokens.
- **Sidebar:** rows "icon + name + counter" 36 px high, wider field and inner paddings, section headings 12 px gray with 19.5 px above, hover highlight (`surface.hover`), the selected chat filled with `surface.selected` and no outline. The collapsed rail uses the same icons.
- **Chat icon (revised after the user's review of the build):**
  - A chat with an emoji shows the emoji as is, with no background, in a slot the size of a tile (`layout.tile.size`, 22.75 px) so that names stay aligned. Inbox always has its emoji.
  - A chat without an emoji shows a letter tile: a rounded square (`radius.tile`, `layout.tile.size`) filled with one of the tile colors and holding the first letter of the title (uppercase, first grapheme found with `Intl.Segmenter`; leading spaces, punctuation and emoji are skipped; `#` if there is no letter or digit), white (`text.primary`).
  - "No emoji" means the stored icon is empty **or equals the default `💬`**: Rust stores `DEFAULT_ICON` (`crates/kinige-domain/src/chat.rs`) when the user picked none, and the Telegram import uses it too (slice 3 rule "no emoji: 💬"). Only the display treats `💬` as "no emoji"; the data, Rust and sync do not change. A user who really wants 💬 gets a letter tile.
  - The tile color comes from the chat id: a 32-bit FNV-1a hash modulo the six tile colors (`tintForId` in `chatLetters.ts`). KINIG-59 (automatic color and a change in the menu) replaces this with the stored color through `SidebarChat.tint`, which already takes precedence (`tintOf`).
  - "Trash" and the profile use an icon or an avatar in a slot of the same size (the icon has no fill); the profile menu items carry icons.
- **Feed and plates, day labels, the "On this day" card, the quote and the reply line, the input field:** feed margins, plate paddings, gaps, radii, the interface font size.
- **Settings window:** the section tree (36 px rows, rounded fill, hover), the page (margins, title, groups and rows roomier), segments, shortcut rows, path, checkboxes.
- **Dialogs and windows:** the modal, "New chat / Rename / Emoji", trash confirmations, the context menu, import, recovery ("Database is damaged"), trash, search (the field stays on top, only sizes and paddings change), the quick capture window (context plates and the button take the new plate, font and button-height tokens; the panel's own padding is unchanged, the OS window width is unchanged, the initial height goes 122 → 123 px to match rounding up in `capture_resize`), the quote in an entry plate, and "Visible chats" with the access log (paddings in the new rhythm).
- **Storybook stories** for the changed components: Russian and English, normal and large text, a long name, letter tiles of all colors next to plain emoji (also in the collapsed rail), keyboard focus, wrapping of a long checkbox label. Hover is shown by the sidebar stories through the `data-story-hover` attribute and a rule in `sidebar-stories.css` (`:hover` cannot be set in a story); there is no separate hover story for the settings tree or the menu. Baselines are taken on GitHub (`visual-update.yml`).
- **Token test:** the new palette roles (`surface.hover`, tiles) are set and pass the "color / background" pairs (`contrastPairs.ts`), including `text.primary` on every tile color (≥ 4.5:1). Unit tests cover the first-letter extraction (Cyrillic, Latin, leading spaces and punctuation, emoji-first titles, combining marks, junk input), the "no emoji" rule and the deterministic tile color.
- **Demo data:** `seed_demo` adds three chats without an emoji ("Проекты", "Linux notes", "Мама"), so the real-window screenshots show letter tiles; the imported Telegram chat "Анна" shows "А".

## Not included
- New functions, texts, screens, animations and toasts; a light theme.
- Choosing a chat color and exposing `color` in `ChatSummary` (Rust and the schema do not change; today `chat.color` in the database is always empty, see "Open questions"). Until KINIG-59 the letter-tile color is derived from the chat id in the frontend (see "Chat icon"); stories set it explicitly through `SidebarChat.tint`.
- The OS window of quick capture: its width and height limits (`layout.capture.*`) match Rust and do not change; the initial height in `tauri.conf.json` goes 122 → 123 (a configuration value, not Rust code).
- The size of the "Settings" window (`layout.settings.window-*`): Rust sets it.
- The sizes of H1-H3 headings inside an entry (the density of entry text was chosen by the user, ADR-0004) and the entry text size (13 px).
- Letter tiles in search results, in the trash plate and in the "Move to chat" submenu: they keep the plain stored emoji (so a default `💬` is still shown there).
- New icons outside Lucide; fonts and the surface palette stay.

## What "done" looks like
- The main window sidebar on a screenshot is closer to the reference in rhythm: 36 px rows, plain emoji and letter tiles on one vertical line, quiet headings with space, a filled rounded selected item, icons at the bottom. The narrow window loses nothing (worse is acceptable).
- Every other area follows the same values: nowhere are the old tight paddings or the small font left.
- The selected row is clearly more visible than the row under the mouse; a record dragged onto a chat under the pointer keeps the drop-target fill.
- Hover is shown in sidebar stories; a long checkbox label wraps instead of being cut off.

## Checks
- In `web/`: `npm ci && npm run tokens && npm run typecheck && npm run lint && npm test && npm run build-storybook` are green; the contrast of the new pairs passes (hover 1.15:1, other fills 1.2:1); "no raw values" is green; files ≤ 400 lines; a CSS test keeps the drop-target fill above the hover fill.
- CI on the branch is green; the Storybook baselines are updated by the bot (one theme).
- Real-window screenshots (`screens.yml`, existing scenarios): `docs/screens/5/` (main window: sidebar, feed, "On this day" card, reply, large text, English) and `docs/screens/4b/` (the "Settings" window: sections, shortcuts, large text, minimum size). Older versions stay in `main` for before / after comparison.

## Touches sensitive areas
No: no schema, sync, encryption or IPC changes, Rust code does not change. No new dependencies.

## Open questions
- Chat color: the `chat.color` column exists but is always empty and is not returned in `ChatSummary`, so there is nowhere to choose a color. The user chose "automatic + change in the menu" (KINIG-59); it is a separate task after D2 and needs a Rust change. In D2 the letter-tile color is derived from the chat id in the frontend.
